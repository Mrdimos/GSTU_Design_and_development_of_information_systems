# Практикум: Проектирование и разработка корпоративных информационных систем

Специальность 6-05-0611-01 «Информационные системы и технологии», 4-й курс.

## Источник истины

`praktikum_korporativnye_is_30_variantov.md` — единый исходный документ. Файл `Общие_указания.md` и `lab_01`…`lab_10` в комплекте сгенерированы из него. При изменении содержания сначала редактируется единый документ, затем заново формируются отдельные файлы; ручное редактирование производных файлов не допускается.

## Состав комплекта

- `praktikum_korporativnye_is_30_variantov.md` — полный практикум: общие указания и все 10 лабораторных.
- `Общие_указания.md` — варианты, общие требования, оценивание и интеграционный чек-лист.
- `lab_01`…`lab_10` — отдельные выдаваемые студентам лабораторные, сгенерированные из полного документа.
- `lab_06_users_schema.sql` — стартовая схема `users` для ЛР6.
- `lab_08_users_password_migration.sql` — миграция `password_hash` для ЛР8.
- `lab_08_refresh_tokens_migration.sql` — миграция таблицы refresh-токенов для ЛР8.
- `docker-compose.yml` — локальный Redis для хранилища сессий в ЛР7.
- `starter/` — стартовый каркас Node.js, примеры репозитория/SQLite, Redis-сессии, OpenAPI и клиента Socket.IO.

## Общие правила

- Один студент использует один и тот же вариант во всех десяти лабораторных.
- Нагрузка: ЛР1–ЛР7 по 2 академических часа, ЛР8–ЛР10 по 4; всего 26 часов. Для заочного отделения — 6 часов.
- Секреты и реальные персональные данные не включаются в исходники; `.env`, `node_modules/` и локальная БД исключаются из Git.
- В студенческий пакет входят отдельные `lab_XX`, `Общие_указания.md`, `lab_06_users_schema.sql`, `lab_08_users_password_migration.sql`, `lab_08_refresh_tokens_migration.sql`, `docker-compose.yml` и каталог `starter/` с каркасом проекта, примером Redis-подключения, OpenAPI и клиентом Socket.IO. Служебные материалы преподавателя не включаются в студенческую сдачу.

## Базовые роли

Для публичной регистрации использовать только наименее привилегированную роль, предусмотренную заданием своего варианта ЛР8; не принимать роль из тела запроса. Выбранную базовую роль для публичной регистрации обязательно зафиксировать в README проекта студента и не принимать роль из тела запроса. Системная роль `admin` управляет пользователями и `/admin`; предметные роли `*_admin` не получают системные права автоматически.
