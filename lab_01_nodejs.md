# Лабораторная работа № 1. Развёртывание среды и проектирование модульного приложения Node.js

> Общие правила, таблица вариантов, соглашения по данным/API и шкала оценивания: [`Общие_указания.md`](Общие_указания.md).

**Трудоёмкость:** 2 академических часа.  
**Цель:** Создать воспроизводимую среду Node.js и спроектировать модульный каркас корпоративного приложения.  
**Основные понятия:** Node.js, V8, Event Loop, npm, package.json, CommonJS и ES Modules, асинхронный и синхронный код.

### Теоретическая справка

Node.js позволяет выполнять JavaScript вне браузера и предоставляет API для сети, файлов и процессов. V8 исполняет JavaScript, а Event Loop координирует callbacks ввода-вывода и фазы `timers`, `pending callbacks`, `poll`, `check` и `close callbacks`. После выполнения callback Node.js обрабатывает очередь `process.nextTick`, затем очередь Promise/microtask; детали порядка зависят от контекста выполнения и версии Node.js. `setImmediate()` выполняется в фазе `check`; порядок `setTimeout(fn, 0)` и `setImmediate()` на верхнем уровне модуля не следует считать гарантированным, а внутри callback ввода-вывода часто наблюдается выполнение `setImmediate()` раньше таймера. npm управляет зависимостями и командами проекта. Модульность уменьшает связанность: точка входа запускает приложение, сервисы реализуют бизнес-правила, утилиты решают общие задачи.

### Индивидуальное задание

Выполните общий алгоритм ниже, а предметную логику возьмите из строки своего варианта в таблице «Индивидуальные требования по вариантам» для этой лабораторной. Не заменяйте индивидуальное требование универсальным примером.

**Обязательный минимум:** все пронумерованные пункты этого раздела, кроме явно перенесённых в «Углублённую часть».

1. Установить актуальную LTS-версию Node.js и проверить node --version и npm --version.
2. Создать проект, инициализировать package.json, определить команду запуска и минимальную документацию README.md.
3. Выбрать ES Modules (type: module) либо CommonJS и последовательно использовать один формат модулей.
4. Разделить код на app/ или src/: config, domain/services, utils и entry point; не помещать всю логику в один файл.
5. Создать модуль предметной сущности, сервис с базовыми операциями над тестовыми объектами и модуль форматирования результата.
6. Продемонстрировать синхронный код, `process.nextTick`, Promise-микрозадачу, `setTimeout(0)` и `setImmediate`; повторить сравнение внутри callback `fs`; объяснить наблюдаемый порядок и отметить, почему порядок `setTimeout(0)`/`setImmediate` в основном модуле не гарантирован.
7. Запустить проект npm-скриптом, проверить корректную работу и обработку хотя бы одной ошибочной ситуации.
